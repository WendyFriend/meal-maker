# Working conventions

- My Journal uses `client/MyJournal.tsx`, `client/journal/`, and `client/services/journalService.ts`. Entries snapshot the displayed meal portions and use local-day boundaries, not UTC calendar days. The table and RLS live in `supabase/migrations/202610290001_food_journal.sql`.
- Recipe Detail renames in place: the name becomes an auto-growing underlined `textarea` (no box; same font, width and lines as the heading; Enter saves, Esc cancels, line breaks become spaces) tied to a hidden form, and ✕ "Edit Name" ✓ appear in the app header via `onNameEditingChange` (the `page-header-create-recipe page-header-name-edit` header stays visible while typing on mobile). The + stays so nothing reflows.
- Saved meal edits are handled by `client/RecipeDetail.tsx`; `App.tsx` persists them with `updateRecipe` and passes saved overrides to the mounted My Meals list. Like My Ingredients and My Diary, My Recipes does not reload when its tab or the app is reopened (pull to refresh does); a recipe made in Create Recipe is passed back as `createdRecipes`, shown on top at once (search cleared, scrolled into view, a one-off `saved-collection-row-new` highlight) and cleared on the next reload. Instructions editing lives in the shared `MealInstructions` component.
- My Ingredients and My Meals share `useCollectionSelection` and `CollectionSelection` controls for long press and bulk deletion, and render rows with `client/components/SavedCollectionRow.tsx` in one grouped `saved-collection-list` (picture, name and optional detail, then a chevron; My Recipes passes Add to My Diary as `action` in the chevron's place; while selecting, the check takes that same column, so rows never reflow). Keep both behaviours and looks consistent. Selection is iOS-style and moves nothing: `CollectionTitle` turns the title into "N Selected" and `SelectionActions` replaces the title row's icons in place (Select all, extra actions, trash with a `Popover` confirm, ✕); no floating toolbar, no add button, no extra controls row. My Recipes also duplicates (a `SelectionActions` action, and the context menu): copies are named Finder-style ("X copy", "X copy 2"), saved oldest first, shown on top highlighted, with a "Recipe duplicated." toast.
- Recipe Detail and Create Recipe share one layout: name, a `NutritionOverview` with the `nutrition-overview-card` class (`MealResult` `summaryVariant="card"`), then `DetailTabs` (Ingredients | Key Nutrients | Steps) with `DetailTabPanel` from `client/components/DetailTabs.tsx`. Keep tab names, order and card styling in those shared pieces. Entering edit mode must not move content: Recipe Detail keeps its header actions (+ or plan-meal ★) while editing ingredients or steps, the name stays the same (disabled) tappable block, section ✕/✓ overlap the 40px section header, and ingredient rows in edit mode pass `showChevron="space"` so the hidden › keeps names wrapping the same.
- My Diary "Add meal" (a plain coral ＋ glyph at the end of the title row, `journal-add-meal-button`, styled like My Recipes' title icons; the Diary title area uses the same padding, side margins, title size and 28px gap as My Recipes and My Ingredients; always shown in the same place, disabled rather than hidden while loading, lifting or creating a new meal; tapping it mid-edit saves that edit via save-on-leave; the empty day's hint points to it) opens `client/journal/AddMealSheet.tsx`, built on `components/ActionSheet` like the Add Ingredient sheet. Recipes are copied into a journal entry (no link back), so plan edits never change the recipe. "Create a new one" stays on My Diary: MyJournal's `newMeal` adds an unsaved card at the end of the list, expanded and in ingredient edit mode (`JournalMealIngredients` `isNew`) with the ingredient field focused and a muted "New meal" name. ✓ or save-on-leave creates it with `saveJournalEntry` (plan only, never My Recipes), named by `defaultMealName` and timed by `nextPlanTime` from `client/journal/planMeal.ts`, with a "Meal added." toast; the card keeps its row key (`rowKeys`) so it stays mounted. Leaving an empty new meal drops it silently; ✕ drops it with a "Meal discarded." Undo. Rename by tapping the name while editing (below) or via Meal Detail. Add ingredient and the meal total are hidden while its name field is open or any field in the meal has focus, so nothing big sits under the thumb above the keyboard. Entering ingredients is one keyboard session: Enter on a name (or a picked suggestion) adds it and focuses its weight (selected, so typing replaces it); Enter on a weight opens the next name; Enter on an empty name finishes (`enterKeyHint` is next/done to match). In view mode, tapping an ingredient's weight starts editing with that weight focused, and a small ＋ (`journal-add-ingredient`, right-aligned under the weight steppers' ＋, in the same place in both modes; it replaced the full-width Add ingredient button) starts editing with the name field open. While editing (the › hidden as `showChevron="space"`), the row's picture opens the nutrition sheet (`ingredient-thumbnail-button`, `display: contents`; a labelled button when `onNameClick` renames, otherwise a pointer-only shortcut); the sheet's fixes go into the draft (✓ or leaving saves, ✕ discards). My Diary's ingredient name and weight fields (adding and correcting) are an underline in the row's own type (≥16px so iOS never zooms on focus), like the meal name, not a box. Tapping an added ingredient's name while editing corrects it in place (`IngredientSectionRow` `onNameClick`/`nameEditor` with the same `RecipeIngredientNameInput`, filled in, caret at the end, no row height change): Enter, a pick or leaving renames it with that name's nutrition and keeps its weight; Esc or an emptied field keeps the old name. While adding or renaming, `.journal-meal-card:has(.ingredient-suggestions)` lets search results overflow the card (it ends at the field while typing, so they were clipped). Focus moves inside the key press via `flushSync` so mobile keyboards stay up, and `revealAboveKeyboard` keeps `--keyboard-inset` for a short grace after blur so moving between fields doesn't jump the page.
- On My Diary, the whole meal row only expands and collapses the meal; its name is never a link and has no chevron. The `plan-meal-detail` page opens from the meal menu's View Details. Long press, right-click and Alt+Arrow are on the whole row (`journal-meal-row`); long press and right-click also work on the open meal's ingredients area outside editing (`contentPressProps` on `journal-meal-expand-inner`, `journal-meal-expand-pressable` turns off text selection and the iOS callout there; sheets and popups bubbling through React are ignored via `MEAL_OVERLAYS`), with the menu opening at the press point. The page is `RecipeDetail` with `variant="plan-meal"` (parent My Diary): name and ingredient edits save back to the plan entry via `updateJournalEntryName` / `updateJournalEntryIngredients` (never to My Recipes; the name uses the same header ✕ "Edit Name" ✓ as Recipe Detail), steps are not editable, and MealResult's star saves a copy to My Recipes. Save toasts (star, Add to My Diary) appear on tap and are withdrawn if the request fails. Toast messages end with a full stop.
- My Diary's ingredient nutrition sheets are editable (`IngredientSectionRow` `onSaveNutrition` → `IngredientNutritionSheet` `onSave`): the "Doesn’t look right?" fixes replace that entry's nutrition, keeping its typed name and weight, and save at once with `onSave`; a matching saved ingredient is updated too, as in Create Recipe. Meal Maker's generated Meal Result does the same (`MealResult` `editableIngredientNutrition`, with `onIngredientStarAuthRequired` for guests; fixes change that meal only, via `fromSheet` in `client/utils/mealIngredient.ts`, shared with My Diary). Recipe Detail rows stay read-only. Their title is also tappable (`IngredientSectionRow` `onRenameNutrition` → `NutritionDialog` `onRename`): only the title changes, into the title-styled underlined `textarea` (shared `useAutoGrowTextarea`, as in Recipe Detail; Enter, ✓, a tap outside the field (not a scroll) or closing the sheet saves; Esc or ✕ cancels), with ✕ and ✓ (no title) in the sheet's top bar; nothing else is added or moves. Saving renames the diary entry only (an already-saved ingredient is renamed in My Ingredients too, silently), keeps its nutrition, weight and open sheet (view rows are keyed by position), and marks missing micronutrients unavailable so the new name never looks up another food. The top bar's ☆ (`ingredient-sheet-star`, in the ✓ column, shown with `onRename` and an `IngredientCollectionContext`) saves the ingredient under its name to My Ingredients, and the filled ★ removes it (`IngredientCollectionContext` `remove`): it changes and shows a sticky bottom toast on tap ("Saved to My Ingredients." with View via `open`, or "Removed from My Ingredients."), both withdrawn if the request fails.
- My Diary ingredient edits save on leave (`client/hooks/useSaveOnLeave.ts`): a tap (not a scroll) outside the meal, collapsing it, another page or date, hiding the app, or unmounting saves like ✓, including a name still in the field; only ✕ discards. Surfaces opened from the edit (dialogs, popovers, listboxes, menus, toasts) don't count as leaving. While a meal is being edited its row shows only the name (not a link; `journal-meal-row-editing`). Tapping that name (`journal-meal-name-button`, `Rename X`) renames the meal as part of the edit (no separate Rename menu item or double tap; a tap on the row expands it): it becomes `journal/MealNameField`, an underlined auto-growing `textarea` in the same type (empty with the muted name as placeholder for a new meal); Enter or a tap elsewhere closes it, Esc or an emptied field restores the name. MyJournal keeps `nameDrafts` by row key; ✓ or save-on-leave saves the name after the ingredients (`updateJournalEntryName`, or the new meal's `mealName`; JournalMealIngredients `nameChanged` makes a name-only edit save), ✕ drops it and its Undo restores it (`onDiscardName`), with no collapse chevron and no long-press reorder. Its ✕ / ✓ go in the app header as ✕ "Edit Meal" ✓ ("New Meal" for a new one) via `JournalMealIngredients` `onHeaderActions` → MyJournal `onEditActionsChange` → App → `PageHeader` `editActions` (the `page-header-name-edit` header, marked `data-part-of-edit` so tapping it never saves on leave); without a host (e.g. MyJournal tests) they stay in the meal row. and ✕ shows a "Changes discarded." Undo toast when something changed.
